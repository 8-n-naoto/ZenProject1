# 精算方法の調査（現金／送金アプリ運用の比較）

**結論: アプリ内に決済機能は持たない。** 「誰が誰にいくら払うか」を出すところまでをアプリの仕事とし、
実際のお金のやり取りは参加者が使い慣れた手段（現金・送金アプリ・銀行振込）に任せる。

理由は3つ。

1. コミケの共同購入は **同じ場にいる少人数**で行うので、現金がその場で完結する場面が多い
2. 決済を持つと **資金決済法・本人確認・返金対応**が絡み、個人開発の範囲を超える
3. 送金アプリは既に十分普及していて、アプリが仲介する価値が小さい

以下、判断の根拠。

## 2. アプリ内決済を採用しない理由（詳細）

### 法規制

他人のお金を預かって送る仕組みは、資金決済法上の **資金移動業**にあたる可能性がある。
登録には供託金・体制整備・当局対応が必要で、個人開発では現実的でない。

これを避けるには決済代行（Stripe 等）を挟むことになるが、それでも次が残る。

- **本人確認**: 受取側の口座登録・本人確認書類の提出が必要
- **返金・チャージバック**: 「買えなかった」「金額が違う」の申し立てにアプリ側が対応する義務
- **手数料**: 決済ごとに3.6%前後。1,000円の精算で36円は、参加者から見ると割に合わない
- **入金サイクル**: 受取側に届くのが数日後。現金・送金アプリの即時性に劣る

### 実際の使われ方との不一致

このアプリの想定は「同じイベントに一緒に行く仲間内での共同購入」。
そもそも顔を合わせているので、**現金か送金アプリで完結する**。
アプリが決済を仲介しても、手数料と待ち時間が増えるだけになる。

## 3. では何をするか — 「払いやすくする」ことに徹する

決済を持たない代わりに、次を丁寧に作る。

| やること | 実装状況 |
| --- | --- |
| 送金回数を最小にする（相殺） | 実装済み。`SettlementService::minimalTransfers()` |
| 「誰が誰にいくら」を一目で分かる形にする | 実装済み。精算リスト画面 |
| チャットに貼って共有できるテキストを出す | 実装済み。「まとめを共有する」ボタン |
| 払ったこと・受け取ったことを記録する | 実装済み。支払い報告 → 受取確認の2段階 |
| 何に対する支払いかを遡れる | 実装済み。精算の内訳画面 |
| 未精算が残っていることを忘れさせない | 実装済み。ホームの「やること」と「未精算のまとめ」 |
| 記録を手元に残す | 実装済み。精算リストのCSVエクスポート |

**送金回数の最小化は、手数料ゼロの手段（現金・送金アプリ）でも効く。**
4人で12件の貸し借りがあっても、相殺すれば送金は2〜3回で済む。
これが実質的にいちばん効果の大きい「手数料削減」になっている。

## 4. 運用としての推奨（利用者向けの目安）

| 状況 | 推奨 |
| --- | --- |
| 会場で解散前に精算する | **現金**。おつりが出ないよう、精算リストの金額を見せながら渡す |
| 帰宅後に精算する | **送金アプリ**。精算リストのテキストをチャットに貼ってから送る |
| 1万円を超える | **送金アプリか銀行振込**。現金の持ち歩きを避ける |
| 相手と面識が薄い | **送金アプリ**。口座番号を教えずに済む |

どの手段で払ったかはアプリでは区別しない。
支払った側が「支払ったことを報告する」、受け取った側が「受け取った」を押せば精算完了になる。

## 5. 見送ったが、将来検討しうるもの

| 案 | 内容 | 見送る理由 / 再検討の条件 |
| --- | --- | --- |
| 送金アプリへのディープリンク | 「PayPayで送る」を押すと金額入りで起動 | 各社の仕様が公開されておらず、変更に追随できない。公式に個人間送金のリンク仕様が出たら再検討 |
| 支払い方法の記録 | 現金／送金アプリ／振込 のどれで払ったかを残す | 精算の正しさには関係しない。「あとで見返したい」という要望が実際に出たら追加する |
| 請求書PDFの発行 | 精算内容をPDFで出す | 仲間内では過剰。CSVエクスポートで足りている |
| 立替上限の警告 | 1人の立替が偏りすぎたら知らせる | 予算機能で残高が見えるようになったので、まずはそれで様子を見る |

---

## 6. 判断のまとめ

- アプリ内決済は **作らない**（法規制・手数料・実際の使われ方の3点から）
- アプリの責務は **「いくら払えばよいかを、迷いなく分かる形で示す」** ところまで
- 実決済の導入可否は、**冬コミでの実運用のあとに、実際に困ったかどうかで判断する**
